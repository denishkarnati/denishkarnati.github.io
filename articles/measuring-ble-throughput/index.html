BLE / ZEPHYR / MEASUREMENT

Measure BLE throughput at the application boundary

Count useful bytes, sequence gaps, and data age before tuning the link.

Technical guide · Dinesh Karnati · October 2026

Define throughput

Radio bitrate, submitted notification bytes, and useful bytes received by a host are different quantities. For a sensor stream, begin with samples per second multiplied by bytes per frame, including metadata.

For example, 250 frames/s with two 3-byte channels and 6 metadata bytes requires 3,000 application bytes/s. These are hypothetical inputs. The calculation establishes demand, not measured connection capacity. Framing, buffering, retries, and host behavior still affect delivery.

Record the connected link

Zephyr’s MTU sample explains that both peers’ ATT settings matter and that ATT MTU and HCI ACL packet size are separate settings. Increasing MTU alone does not establish a throughput improvement.

Record firmware and host versions, peer, exchanged MTU, connection interval, PHY, and buffer settings. Put a sequence number in each application frame. Count produced frames, submitted frames, and unique received frames separately.

Measure a fixed window

After connection setup, count useful received bytes over elapsed host time. Record gaps, duplicates, queue high-water mark, and data age. A stream can deliver all queued data while becoming too old to be useful.

Decouple receive handling from plot rendering and disk writes. Compare a minimal receive-and-count test with the complete plotting application before attributing a slowdown to the radio. A receiver that redraws for each packet may create its own backlog.

Change one variable

Compare payload batching, MTU, interval, or host workload separately. Keep the configuration with each result and repeat under comparable conditions. Test a disconnect and record the buffer, loss, and recovery policy.

A reproducible report includes duration, useful bytes/s, produced and received counts, loss definition, maximum queue depth, and latency definition. Without synchronized clocks, distinguish host inter-arrival time from acquisition-to-host latency. The linked browser illustration explores a payload budget; a device result needs a recorded run.
