01 / PROJECT CONTEXT

What I worked on

Two projects in digital logic

My digital-design work includes a 32-bit single-cycle MIPS processor in VHDL and separate FIFO designs in Verilog. I designed and emulated the processor using Quartus Prime and ModelSim. The FIFO work included synchronous and asynchronous designs with 8 × 8 memory.

These are distinct projects. The processor explores instruction execution and datapath logic. The FIFO explores ordered storage, retrieval, and status flags. Grouping them here highlights the shared workflow of describing logic, applying testbench stimulus, and inspecting simulation behavior.

Processor design and verification

The MIPS project gave me a setting for working with RTL and simulation tools. The documented design is single-cycle: the execution behavior needs to be considered as a complete instruction path. The cover reproduces the processor architecture reference included in my published article. It shows the controller, program counter, register file, and ALU; it is not presented as an exported Quartus schematic or a ModelSim result.

The interactive model below exposes arithmetic, load/store, and branch examples through five explanatory stages. Those stages make data and control movement visible; they are not a clock-accurate simulation of my single-cycle RTL. Registers, memory, and FIFO state can be inspected separately.

Model boundaries

Instruction-level teaching subset: 32 registers, 16 memory words, unsigned wrapping arithmetic, and no branch delay slots. FIFO clocks are independent software timers, not CDC/metastability verification. Quartus/ModelSim remain the actual RTL verification tools.

Try these experiments

  1. Step through the Memory program stage by stage; inspect SW, LW, and register write-back.
  2. Run the Branch program and follow the program counter as the loop exits.
  3. Open FIFO, set producer faster than consumer, and inspect overflow rejection and pointer wrap.
04 / ENGINEERING NOTES

Decisions worth making explicit.

BoundaryWhy it mattersWhat to inspect
Instruction state

The destination register must receive the intended result at write-back.

Follow fetch, decode, execute, memory, and write-back without conflating an animation with a clock-accurate design.

Memory boundaries

A word access must have a valid aligned address in the model.

Inspect address calculation, memory read/write, and rejected out-of-range operations.

FIFO boundaries

Full and empty conditions are explicit control states.

Exercise wrap-around, rejected writes/reads, almost-full/empty flags, and pointer representations.
