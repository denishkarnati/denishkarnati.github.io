01

Two projects in digital logic

My digital-design work includes a 32-bit single-cycle MIPS processor in VHDL and separate FIFO designs in Verilog. I designed and emulated the processor using Quartus Prime and ModelSim. The FIFO work included synchronous and asynchronous designs with 8 × 8 memory.

These are distinct projects. The processor explores instruction execution and datapath logic. The FIFO explores ordered storage, retrieval, and status flags. Grouping them here highlights the shared workflow of describing logic, applying testbench stimulus, and inspecting simulation behavior.

02

Processor design and verification

The MIPS project gave me a setting for working with RTL and simulation tools. The documented design is single-cycle: the execution behavior needs to be considered as a complete instruction path. The cover reproduces the processor architecture reference included in my published article. It shows the controller, program counter, register file, and ALU; it is not presented as an exported Quartus schematic or a ModelSim result.

The arithmetic walkthrough focuses on a single operation. It accepts two register values and demonstrates an ADD result with a register write-back message, making the movement from operands to destination register easy to inspect.

03

FIFO behavior at the boundaries

For the FIFO project, I implemented full, empty, almost-full, and almost-empty signals and created a testbench for data storage and retrieval. The key behaviors are ordering and capacity: data should be read in the same order it was written, and boundary conditions need explicit handling.

The browser view uses eight visible slots to make those behaviors easy to examine. A write at capacity is rejected without overwriting data. A read on an empty queue is rejected. This explains queue behavior without pretending to simulate clock-domain crossing or reproduce the Verilog testbench.

04

Use the two views

Change the register inputs and execute ADD, then switch to the FIFO tab. Write several bytes, read a few, and inspect the occupancy and full/empty flags. The oldest byte always leaves first.

The two views emphasize different properties: arithmetic produces a new register value, while a queue preserves the order of stored values. RTL simulation and testbenches remain the verification environment for the hardware designs.
