01 / MY CONTRIBUTION

Problem

I designed and emulated a 32-bit single-cycle MIPS processor in VHDL and implemented separate FIFO designs in Verilog. These projects explore instruction execution and ordered data storage through RTL and testbenches.

Constraint

The processor needs a coherent instruction path through control, register access, the ALU, and memory. A FIFO must preserve ordering while making full and empty conditions explicit. These are different verification problems, so the two projects are described separately.

Decision

For the processor, I used VHDL with Quartus Prime and ModelSim to design and validate the 32-bit single-cycle implementation. For the FIFO work, I implemented synchronous and asynchronous designs with 8 × 8 memory, boundary flags, and a testbench for storage and retrieval.

Result

The MIPS project ran October–December 2023. The FIFO project ran February–May 2024 and included full / empty and almost-full / almost-empty status. My contribution covered RTL implementation and simulation-based validation.

Execution model

Hardware described in VHDL / Verilog, with simulator-driven testbench stimulus. This is RTL design, rather than an RTOS or bare-metal firmware application.

Toolchain & bench

VHDL, Verilog, Quartus Prime, ModelSim, and RTL testbenches.

04 / ENGINEERING REVIEW

Debugging approach

For RTL, inspect stimulus, control signals, register or memory updates, and boundary flags together. A useful FIFO trace includes both accepted and rejected operations at full and empty boundaries.

Trade-offs and next improvements

Instruction coverage

The supported instruction list and its testbench coverage should accompany any processor implementation.

Clock domains

An asynchronous FIFO needs clock-domain-crossing review beyond a software illustration of two timers.

Next evidence

A public RTL repository with testbench commands and waveform captures would let another engineer reproduce the checks.
