01

The engineering problem

A wearable sensing system needs more than a sensor reading. Firmware must coordinate interfaces, collect samples at the right time, identify the device, and move data to a host that an engineer can inspect. Those responsibilities cross the boundary between electronics and software.

At Texas A&M University, my work includes embedded firmware for wearable sensing and biomedical test systems. I use C/C++ with nRF52840 and nRF52832 targets, Zephyr RTOS, and supporting hardware platforms. The lab imagery here provides context for the wearable research; my contribution is firmware, hardware integration, and engineering tools.

02

My contribution across the signal chain

My sensor-integration work includes ADS131M04/M02 ADCs, MAX30208 temperature sensing, BNO080 inertial sensing, and MAX20303 power management. SPI, I2C, GPIO, interrupts, and timing all matter when these parts become one acquisition system.

On the data path, I implement interrupt-driven multichannel acquisition and BLE GATT streaming, including device identification and battery telemetry. On the host, I build Python tools using Bleak, PySide6, and pyqtgraph for device discovery, selection, live plotting, battery monitoring, and CSV recording.

03

Making the hardware observable

A plot is useful only when the hardware and data path can be understood. My bring-up and debugging work uses oscilloscopes, logic analyzers, multimeters, and SEGGER RTT to investigate communication, timing, ADC, power-rail, and sensor-interface issues.

That combination of board-level inspection and host-side visualization makes it possible to reason about a problem across several layers. I also characterize PMIC behavior, charging, battery discharge, and voltage rails as part of integrating wearable prototypes into testable systems.
