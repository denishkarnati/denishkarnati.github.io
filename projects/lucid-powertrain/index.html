01 / PROJECT CONTEXT

What I worked on

The role at Lucid

At Lucid, I worked on platform software for electric-vehicle powertrain ECUs. My work covered low-level drivers, middleware, software integration, and debugging at the hardware–software boundary. The role ran from January 2024 to April 2026, following an embedded software engineering internship from August to December 2023.

The engineering focus was real-time platform behavior: bringing modules together on ECU hardware, resolving integration issues, and supporting validation within automotive development and safety processes.

From modules to an integrated ECU

I worked across AUTOSAR BSW, RTE, and MCAL layers while integrating platform and application software. My responsibilities included on-chip debugging, code review, and performance-oriented changes to real-time software.

The important distinction is between a software component that works in isolation and a system that behaves correctly when its dependencies are present on the ECU. Debugging at that boundary requires attention to both the software path and the behavior of the target hardware.

04 / ENGINEERING NOTES

Decisions worth making explicit.

BoundaryWhy it mattersWhat to inspect
Command freshness

A new demand value is useful only if a valid message reaches the consumer in time.

Track the age of the last valid frame and a defined timeout threshold.

Fault containment

Communication loss must produce an explicit state transition.

Observe a safe/inhibit output, record the reason, and test recovery conditions.

Reproducibility

An intermittent integration defect needs a repeatable trigger and useful evidence.

Log sequence, time, validity, state transitions, and the condition used to reproduce the problem.
