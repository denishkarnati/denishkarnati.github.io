01 / MY CONTRIBUTION

Problem

Biomedical test setups need firmware and host software that make pressure signals inspectable during experiments. I supported Portenta H7 pressure-monitoring work at Texas A&M’s Optical Bio-Sensing Laboratory.

Constraint

ADC / DAC integration, voltage-domain interfaces, and waveform behavior must agree before a host plot can be interpreted. A physical phantom also needs repeatable bench conditions rather than a display that merely resembles a physiological waveform.

Decision

I integrated the Portenta H7 acquisition path, supported level shifting, and verified waveforms with bench tools. I developed Python test software to inspect the pressure-monitoring experiments and their device interfaces.

Result

My work connected pressure acquisition, ADC / DAC interfaces, waveform verification, and host-side testing. I contributed embedded integration and test software used to investigate the bench signal path.

04 / ENGINEERING REVIEW

Debugging approach

I worked across the electrical interface and software interpretation: inspect the signal and voltage levels, verify the acquisition path, and compare the waveform with host-side observations.

Trade-offs and next improvements

Electrical versus software errors

Check interface levels and signal behavior before treating a decoded waveform as an application defect.

Model versus measurement

A physiological-looking trace needs calibration and an experimental reference to support a measurement claim.

Next evidence

The supplied hardware photo and verification-code capture show the bench and software context. A paired scope trace and acquisition configuration would complete the signal-path evidence.
